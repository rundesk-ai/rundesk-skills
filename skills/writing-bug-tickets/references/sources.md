# Sources

What each source established, and where it shows in the skill. Links verified 2026-10-22.

| Source | Kind | Established | Where |
|---|---|---|---|
| Mozilla, [Bug Writing Guidelines](https://bugzilla.mozilla.org/page.cgi?id=bug-writing.html) | project guidelines | One bug per report ("If you have multiple issues, please file separate bug reports"); steps to reproduce are "the most important part of any bug report"; precise actual and expected results; whether it reproduces at will, occasionally or not at all; operating system, version and build. | Shape; one failure per ticket; Expected and Actual; Tested with frequency and environment. |
| Simon Tatham, [How to Report Bugs Effectively](https://untroubled.org/articles/bugs.html) (1999) | practitioner | "The aim of a bug report is to enable the programmer to see the program failing in front of them"; make clear what are actual facts and what is speculation; "most intermittent faults are not truly intermittent". | Purpose; facts, not theories; "Suspected:" notes; recording the pattern of an intermittent failure. |
| Chromium, [Bug Life Cycle and Reporting Guidelines](https://www.chromium.org/for-testers/bug-reporting-guidelines) | project guidelines | "If a bug can be reduced to a simplified test, then create a simplified test and attach it to the bug"; give detailed steps to replicate. | The smallest set of steps from a known state; attaching rather than pasting. |
| Sauce Labs, [Bug Severity vs. Priority](https://saucelabs.com/resources/blog/bug-severity-vs-priority) | vendor guidance | Severity measures how much a bug impacts the system; priority is the order of fixing, shaped by business impact and likelihood, and is agreed with stakeholders. | Describe impact; leave severity and priority to triage. |
| Trials of the sibling task-ticket guidance on a lead-generation codebase, on two agent providers | recorded experience | Without guidance, agents drafted full tickets from vague reports, padded them with unrequested lines, and wrote long notes. | Ask instead of drafting; the fixed notes shape. |

The source statements are the sources'; how they map onto this skill's rules is this skill's conclusion.
