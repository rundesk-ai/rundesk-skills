# Fallback GitHub issue templates

Use these only when the target repository has no applicable issue template. Select one template,
replace every placeholder, remove comments, and keep every heading in order.

## Bug report

```md
## Problem

<!-- State what happened, who is affected, and why the result is incorrect. -->

## Reproduction

<!-- Give the smallest exact setup and ordered actions that reproduce the problem. -->

## Expected behavior

<!-- State the observable result that should occur instead. -->

## Evidence

<!-- Include fresh, sanitized output, errors, screenshots, source locations, or regression range. -->

## Environment

<!-- Include only relevant versions, commit, operating system, runtime, and configuration names. Never include secret values. -->

## Scope and privacy

<!-- State the affected surface and confirm the report contains no credentials, personal data, private identifiers, or owner-specific paths. -->
```

## Change proposal

```md
## Problem

<!-- State the concrete limitation and who it affects. -->

## Desired outcome

<!-- State the observable outcome the proposal should produce. -->

## Users and value

<!-- Identify who benefits and the measurable or practical value. -->

## Scope and compatibility

<!-- Name affected contracts, compatibility constraints, permissions, dependencies, and migration needs. -->

## Alternatives

<!-- State the existing path or smaller alternative considered. -->

## Validation

<!-- State how automated checks and a representative user path will prove the outcome. -->
```
